# Этап 03 — IDS/IPS на шлюзе ДМЗ

## Цель
Настроить систему обнаружения вторжений Suricata на gw-dmz (в схеме «Firewall + IDS/IPS»). Показать срабатывания на ICMP, подключения к web, XSS и сканирование. По возможности показать режим предотвращения (IPS).

## Что сделать
1. Установи Suricata из репозитория Debian в образ gw-dmz. Режим IDS (af-packet на интерфейсах transit и dmz, интерфейсы находи по IP). Логи `fast.log` и `eve.json` в `/var/log/suricata`, смонтируй том так, чтобы читать с хоста из `gis/stand/logs/` (папку добавь в `.gitignore`).
2. Предустановленные правила (suricata-update) недоступны: сети internal. Пиши локальные правила `local.rules`, коротко прокомментируй каждое:
   - входящий ICMP echo request из внешней сети;
   - исходящий ICMP echo reply во внешнюю сеть;
   - успешное HTTP/HTTPS-подключение клиента из внешней сети к web;
   - XSS: `<script>` в URI или теле запроса;
   - SQL-инъекция: типичные признаки (`' OR 1=1`, `UNION SELECT`) в URI;
   - сканирование портов (много SYN на разные порты за короткое время);
   - попытка входа по FTP (USER/PASS).
3. **Опционально (IPS, если останется время):** nftables `queue` на gw-dmz для HTTP к web и правило Suricata `drop` на XSS в режиме NFQUEUE. Проверь, что запрос блокируется, а обычные запросы проходят. Если не вышло за разумное время, запиши причину и оставь IDS-режим.
4. Если трафик между зонами из-за режима `protect` не доходит до gw-dmz, проверку ICMP делай в режиме `audit`, а HTTP/XSS/SQLi/FTP-логин в `protect` (они разрешены политикой). Запиши, в каком режиме какая проверка.

## Обязательные проверки (каждая со скрином)
Сначала очисти логи, потом выполни действие, потом покажи свежие записи:
- ICMP: `attacker` → ping web в режиме `audit` → алерт.
- Нормальное подключение: `client` → `curl https://…` → алерт «успешное подключение».
- XSS: `attacker` → `curl "https://198.51.100.1/search.php?q=<script>alert(1)</script>"` → алерт XSS. Сними также страницу в браузере `shot-web.sh` (скрипт сработал на странице).
- SQLi: запрос с `' OR 1=1--` → алерт.
- Сканирование: `nmap -sS` по web → алерт.
- Для каждого алерта покажи и `fast.log`, и фрагмент `eve.json` (например, `jq` по `event_type=alert`).
- Если делал IPS: до/после блокировки XSS.
- Версия Suricata, `suricata -T -c … ` (проверка конфигурации).

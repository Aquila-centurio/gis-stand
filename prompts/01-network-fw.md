# Этап 01 — сети, роутеры, межсетевые экраны

## Цель
Поднять каркас стенда: сети, все узлы-заглушки, маршрутизацию между зонами и nftables на трёх МЭ с режимами `protect`/`audit`.

## Что сделать
1. **Проверка окружения** → `results/00-env.md`: версии docker и compose, ядро, наличие `nf_tables` и возможность создать `wireguard`-интерфейс в контейнере (`ip link add wgtest type wireguard` под `NET_ADMIN`), свободные диск и RAM. Если чего-то нет, остановись и опиши пользователю, что нужно сделать на хосте.
2. Базовый образ `gis-base` и Dockerfile на каждый узел из таблицы в 00-context.md. Пока на сервисных узлах (web, ftp, db, dc, arm1, radius, vpn) достаточно заглушки с нужными адресами. На web временно поставь простой http-сервер на 80, он нужен для проверок.
3. `docker-compose.yml`: проект `gis`, четыре internal-сети со статическими адресами, `cap_add: NET_ADMIN` где нужно, `sysctls: net.ipv4.ip_forward=1` на роутерах. Все маршруты из 00-context.md ставятся в entrypoint.
4. Наборы nftables для fw-ext, gw-dmz, fw-int по политике из 00-context.md. DNAT на fw-ext: 80/443 → web, 51820/udp → vpn. Masquerade на fw-ext для исходящего трафика fw-int. Именованные счётчики на drop-правилах.
5. Скрипты `up.sh`, `down.sh`, `mode.sh protect|audit` и `shot.sh` (спецификация в 00-context.md).

## Обязательные проверки (каждая со скрином)
Сделай их в обоих режимах, где указано:
- `protect`: attacker → ping 192.168.200.10 и 192.168.100.10 не проходит (100% потерь), nmap по 192.168.100.0/24 показывает только разрешённое.
- `protect`: client/attacker → `curl http://198.51.100.1` получает ответ web (через DNAT).
- `protect`: attacker → 198.51.100.1 на порты 21, 22, 5432 закрыты.
- `protect`: web → db:5432 проходит, web → db:22 нет, ftp → db нет.
- `audit`: ping attacker → внутренние сети проходит, маршрутизация между всеми зонами работает.
- `nft list ruleset` каждого из трёх МЭ (скрин по каждому) и вывод счётчиков после проверок (видно, что drop-правила срабатывали).
- `mode.sh` переключает режимы туда и обратно без перезапуска контейнеров. Покажи до/после на одной и той же проверке.
- `ip route` на каждом роутере и traceroute (или `tracepath`) от client до db в режиме `audit` (показывает путь через зоны).

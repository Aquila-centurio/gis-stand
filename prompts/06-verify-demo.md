# Этап 06 — итоговые проверки, сводка, демо для защиты

## Цель
Убедиться, что стенд воспроизводится с нуля и все механизмы работают, собрать единую сводку для отчёта и подготовить сценарий демонстрации на защите.

## Что сделать
1. `stand/scripts/check-all.sh`: неинтерактивный прогон всех ключевых проверок этапов 01–05 (в нужных режимах `protect`/`audit`), на выходе таблица `PASS/FAIL` в `results/06-checks.txt`. Код возврата ненулевой, если есть FAIL.
2. **Чистый прогон:** `down.sh` с удалением томов проекта `gis`, потом `up.sh`, потом `check-all.sh`. Запиши время подъёма и результат. Если что-то не поднимается с нуля (порядок запуска, гонки), исправь (healthcheck/depends_on/ожидания).
3. Пересними скрины, которые устарели из-за правок после этапов, и проверь, что у каждого `.png` есть `.txt`.
4. `stand/scripts/demo.sh`: пошаговая демонстрация на 5–7 минут с паузами между шагами (Enter): схема и состояние узлов → МЭ: ping снаружи не проходит, сайт открывается → переключение `audit`/`protect` → IDS: XSS → алерт → VPN: до/после → домен: вход пользователя → RADIUS/Squid: 407 → 200.
5. Собери `results/00-summary.md`:
   - итоговая топология и фактический IP-план (таблица);
   - узлы: образ, ПО и версии (`dpkg -l` по ключевым пакетам), назначение;
   - таблица замен относительно схемы с причинами (Astra → Debian, pfSense → nftables+Squid, OpenVPN → WireGuard, Windows DC → Samba AD, Secret Net → аналоги, Snort → Suricata, ГОСТ-крипто → обычный TLS);
   - матрица проверок: механизм → проверка → результат → скрин;
   - учебные пароли и учётки стенда;
   - как поднять и остановить стенд, как переключать режимы;
   - известные ограничения (что не реализовано и почему);
   - 8–10 вероятных вопросов на защите с краткими ответами, основанными на реальной конфигурации (например: почему DNAT на fw-ext, зачем два режима, чем IDS отличается от IPS, что в логах видно при XSS, почему web не может ходить в db по ssh, чем заменили Secret Net).
6. Убедись, что в `results/` нет приватных ключей и секретов.

## Обязательные проверки
- `check-all.sh` зелёный после чистого прогона.
- `demo.sh` пройден целиком один раз без ручных правок (результат в `results/06-demo-run.txt`).

# Проект «Стенд ГИС» (ПАСОИБ, УрФУ), вариант 3

Работа ведётся в этой папке (`gis/`). Стенд — Docker Compose на Debian. Только открытое ПО, без Windows и платного софта.

## В начале КАЖДОЙ сессии
1. Прочитай `PROGRESS.md` целиком.
2. Прочитай `prompts/00-context.md` (топология, адреса, политика, правила, шаблоны).
3. Возьми первый незавершённый этап из `PROGRESS.md`, прочитай его файл `prompts/NN-*.md` и работай только над ним.
4. Не переделывай то, что в `PROGRESS.md` отмечено выполненным, без явной причины (причину запиши).

## Правила (коротко; подробности в 00-context.md)
- Обновляй `PROGRESS.md` после каждого значимого шага, а не в конце сессии. Сессия может оборваться в любой момент.
- Результаты этапа пиши в `results/NN-*.md` по шаблону из 00-context.md. Их потом оформят в отчёт в Word, поэтому нужны точные факты.
- Ничего не выдумывай. Вывод команд и скрины только реальные. Не получилось — запиши как есть и опиши обход.
- Хост не трогай: ни iptables/nft/sysctl на хосте, ни системные пакеты. Всё внутри Docker и папки `gis/`. Если нужен `sudo` или установка на хост, остановись и спроси пользователя.
- Не используй `--privileged`, если хватает `cap_add: NET_ADMIN`. Любое исключение запиши в результаты.
- Проект Docker называется `gis`. `docker compose down -v` разрешён только для него.
- Тексты в `results/` и `PROGRESS.md` пиши по-русски. Имена файлов, конфиги и команды на латинице.
- Секреты (ключи WireGuard, пароли стенда) лежат в `stand/secrets/` и не коммитятся. Пароли стенда учебные, их перечисли в `results/00-summary.md`.
- В конце сессии: `PROGRESS.md` актуален, `stand/scripts/up.sh` поднимает стенд с нуля, сделан локальный git-коммит.
